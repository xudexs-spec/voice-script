# 口喷纠错表 · 模板

> **语音输入天生是脏的**——不管哪台手机、哪个输入法，都会有错字、会漏标点。
> 这张表不是"补救"，是你流水线上的一道**固定工序**。
>
> 结构照主流语音转写的标准做法——**两层**：
> **识别前预防**（术语本）＋ **识别后修复**（替换映射）。
>
> 📌 **用法**：把本文件复制成 `口喷纠错表.md`，往里填。**不用一次填完，遇到就加。**

---

## 零、两层怎么分工

| 层 | 名字 | 干什么 | 什么时候看 |
|---|---|---|---|
| 第一层 | **术语本**（表 A） | 列你**一定会说到**的词（专名、行业词、工具名、人名）。读稿前先扫一遍，**看到近音就提高警觉** | 读素材**之前** |
| 第二层 | **替换映射**（表 B） | 记 `听成 X → 实际是 Y`。命中**直接改** | 出稿**当中** |

**为什么要分两层**：
- 只有表 B（修复），每次都得**等错先发生**才改——被动。
- 加上表 A（预防），很多错**根本不会犯**——比如知道你一定会说"樊登"，那听到"反登"立刻就反应过来了。

---

## 一、铁律：这四类一律回问，不自己改

不管表里有没有，都这么办：

| 类型 | 为什么 |
|---|---|
| 🔴 **数字 / 金额 / 时间** | "10 块"听成"18 块"，整条稿的可信度就塌了 |
| 🔴 **人名 / 书名 / 品牌** | 改错就变成造谣 |
| 🔴 **专有名词**（你的行业词、术语、工具名） | 语音识别最爱错的地方 |
| 🔴 **否定词**（不 / 没 / 别 / 无） | "不是"听成"是"，**意思直接反了**，灾难级 |

**处理方式**：不猜。保留原词 + 标 `【? 原词】`，在稿末列成「待你确认」清单。

---

## 二、其余错字的三档处理

| 情况 | 怎么办 |
|---|---|
| **99% 确定**的同音错字 | ✅ 直接改，并在交付的「改的错字」里列出来（`原 → 改`） |
| **有歧义**、改了可能变意思 | ⚠️ 绝不猜。标 `【? 原词】`，列进待确认清单 |
| **听不懂**、整块缺失 | 留 `【这段听不清，你补一句】`，**不替你编** |

> **大小写要写死**——模型不会从音频里猜出 "API" 该大写。

## 五、🔴 五条反污染纪律（比"记得多"更重要）

1. **别把常用词放进表 B。** 往替换表里塞"我们""就是"这种高频词，会把**无关的句子**一起改坏。表里只放**专名、术语、罕见词**。
2. **别过度替换。** 同音词得看上下文——**不是见到就换**。
3. **大小写要写死。** API / token / OAuth / GraphQL 这类，音频里听不出大小写，靠这张表强制。
4. **只记你自己的词。** 不加通用词、不加单音节——那是污染源头。
5. **宁可多问一句，不许猜。** 猜错一个否定词，整条稿意思就反了。

## 六、这张表跟"你怎么说话"是两回事

| | 记不记 |
|---|---|
| **你的语言习惯**（句子长短、垫词、口头禅） | ❌ **别描述** —— 描述了就失真，AI 会从你喷的东西里自己抠（见 `onboarding.md`） |
| **你的输入法常错哪些词** | ✅ **可以直给** —— 这是**客观事实**，写进这张表 |

**主观的别描述，客观的可以直给。** 这条界线分清了，两套机制就不会打架。
